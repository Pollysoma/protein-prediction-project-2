# ContrasTED, Ankh, and EAT: split and evaluation extraction

## ContrasTED

- **Source/version:** Miller et al., supplied `2026.08.28.747864v2.full.pdf`; version posted **6 September 2026**, not 28 August. Pointers below use the paper's printed line numbers. The supplied 27-page PDF ends with references; its cited supplementary tables/Methods are not included. Numbers attributed to supplements below are only those reproduced in the main text. [PDF running header; pp. 22–27]

### Split recipe and exclusions

- Start from **CATH v4.4, classes 1–3** (Mainly Alpha, Mainly Beta, Alpha-Beta); filter the **CATH S100** domain collection. This is a domain benchmark, not whole-protein classification. No more precise CATH file timestamp/checksum is stated. [§4.4, lines 293–301]
- Sample **one representative domain per superfamily** into **disjoint validation and test sets**. Final sizes are **514 validation domains** and **1,028 test domains**, hence respectively 514 and 1,028 query superfamilies. The text does not specify sampling seed, selection distribution, eligible-family rule, initial counts, or whether the validation and test *superfamily sets* overlap; disjoint domains do not imply disjoint labels. [§4.4, lines 293–300; §2.1, line 62]
- Remove **CATH S100 candidate training domains** sharing **≥20% sequence identity to any validation OR test domain**, using **MMseqs2 profile search**, **sensitivity 7.5**, **three iterations**, **80% bidirectional coverage**. Thus the retained lookup is below 20% identity under this operational search/filter criterion; exactly 20% is excluded. [§4.4, lines 295–298]
- **Direction/command uncertainty:** the biological exclusion direction is lookup/training candidates relative to held-out queries. “80% bidirectional coverage” requires coverage in both sequences, but does not by itself document two reciprocal searches. The paper gives no executable command, MMseqs2 version, identity definition, E-value cutoff, or explicit query/profile-building orientation. Do not invent a CLI parameter string or assume this is simple pairwise clustering. [§4.4, lines 295–298]
- Exclude **test superfamilies with no remaining training representatives after filtering**. Final CATH training/lookup: **116,301 domains across 5,659 superfamilies**. The equivalent exclusion rule is not explicitly stated for validation queries. Counts before each exclusion are not given. [§4.4, lines 298–301]
- In **all Table 1 evaluations**, the reference is **only the corresponding CATH training domains**; not the full S100 collection and not validation/test. [§4.4, lines 300–301]
- Exclude domains of length **<16 or >2,000 residues**; map nonstandard amino acids to **X**; concatenate discontinuous CATH segments **in chain order**. The Methods do not separately give counts removed by these preprocessing rules. [§4.1, lines 250–260]
- TED augmentation is separate from lookup construction: start with **TED Gold** consensus labels supported by **both Foldseek and profile-HMM search**; take **S40 representatives**; remove domains sharing **≥20% identity to either CATH validation or test**, using MMseqs2 sequence-profile filtering; retain **11,131,930 TED training domains**. They augment metric learning **only**; lookup remains CATH-only. Exact TED release/date and a full filtering command are not stated here. [§4.4, lines 302–310]
- External **TED Gold NR S20**: exclude domains with **≥20% identity to the entire combined CATH+TED training set**, retain **one representative per superfamily**, giving **869 queries**. The chronological selection/deduplication recipe is not fully specified. [§4.4, lines 311–313; §4.10, lines 394–399]

### Calibration, coverage, precision, and frozen controls

- Frozen features: **final-layer residue mean**, excluding special tokens; ProstT5 `<AA2fold>` and `<fold2AA>` each yield **1,024 dimensions**, concatenated AA∥3Di yields **2,048**. ProtT5 and single-modality controls use identical pooling. These controls are not contrastively trained. [§4.1, lines 250–260]
- Projection outputs are **128-dimensional and L2-normalized**; ContrasTED uses cosine distance **`d(u,v) = 1 - uᵀv`**. Retrieval centroids are **empirical L2-normalized means of projected CATH reference embeddings**, not the learnable training proxy centers. For confidence ranking, frozen embeddings also use **cosine distance**. Frozen-vector preprocessing/normalization order is less explicitly documented than projected-vector normalization. [§4.2, lines 262–269; §4.3, lines 289–291; §4.8, lines 354–360]
- Select each method's **most permissive threshold achieving ≥99% empirical accepted-set precision on S20 validation**, then apply **unchanged to test**. For distance this is the largest accepted distance; accept with **`d ≤ threshold`**. Native confidence metrics: cosine distance for ContrasTED/frozen embeddings, maximum softmax probability for CATHe2, E-value for Foldseek. No minimum accepted validation count or confidence-bound-based selection criterion is stated. [§2.3, lines 132–150; §4.8, lines 356–361]
- Threshold fitting uses **514 validation queries**, not test or database-scale TED queries. All hyperparameters/distance thresholds are chosen exclusively on training/validation before test evaluation. The trainable checkpoint is separately selected by **1-NN top-1 validation accuracy against CATH training**. [§4.5, lines 315–318; §4.9, lines 368–370; §4.10, lines 384–387]
- Main AA∥3Di **centroid** gate: **`d ≤ 0.24048`** (rounded 0.240); **658/1,028 accepted = 64.0% coverage**, **648 correct, 10 errors = 98.5% precision**, **95% CI [97.2, 99.3]**. The 99% validation target is not a promise of ≥99% test precision. [§2.3, lines 134–150; §4.10, lines 384–387]
- Main **1-NN** gate: **`d ≤ 0.178`**, **599/1,028 accepted = 58.3% coverage**, **591 correct, 8 errors**. Precision from these counts is **98.66%** (calculation). Centroid retrieval gains **57 correct assignments** over gated 1-NN despite lower ungated accuracy. Do not attach the centroid threshold to raw 1-NN. [§2.3, lines 143–152]
- Under the same ≥99% validation criterion: **CATHe2 55.9% coverage / 98.8% test precision**; **ProtTucker 36.4% / 97.9%**; **Foldseek 2.3% / 91.7%**. These are method-specific gates, not one shared numerical cutoff. [§2.3, lines 137–142; Fig. 3c]
- **Frozen ProstT5 embeddings have no threshold reaching 99% validation precision**; the main text does not provide a qualifying frozen operating point or exact cutoff. Do not interpret that as zero ungated classification accuracy, and do not generalize the statement to all conceivable frozen pLMs. [§2.3, lines 139–142; Supplementary Table S7 cited there]
- Frozen S20 **1-NN C/A/T/H (%)**: **ProtT5 93.0/83.9/75.5/69.6**, H CI **[66.8,72.3]**; **ProstT5-AA 96.3/90.3/85.3/78.5**, H CI **[76.1,81.0]**; **ProstT5-AA∥3Di 97.6/92.1/88.4/81.9**, H CI **[79.6,84.3]**. [Table 1]
- Frozen **centroid C/A/T/H (%)**: **ProstT5-AA 94.8/85.2/77.3/66.8**, H CI **[63.9,69.6]**; **ProstT5-AA∥3Di 96.0/89.7/83.9/73.2**, H CI **[70.6,76.0]**. These are different retrieval modes from raw EAT 1-NN. [Table 1]
- **Separate absent-superfamily model:** threshold **`0.22579`**, not 0.24048. Fig. 4a shows **64.6% validation accepted / 99.10% validation precision**; Fig. 4b gives CATH test **646 accepted, 10 errors, 98.45% precision** (coverage **62.84%**, calculated). On external TED Gold NR S20 it accepts **688/869**, **10 errors**, **98.55% precision**, CI **[97.34,99.30]** (coverage **79.17%**, calculated). [§2.4, lines 154–165; Fig. 4a–b and caption; §4.10, lines 388–399]
- **Reporting trap:** §2.4 introduces 0.22579 before fully explaining the separate model; Fig. 4 caption clarifies panels a–b use the **50-H-withheld model**, while c–g use the main model at **0.24048**. Fig. 2's canonical seed-40 centroid accuracy **932/1,028 = 90.7%** is likewise not Table 1's **91.4% mean across seeds 40–42**. [Fig. 4 caption; §4.2, lines 268–269; Fig. 2c; Table 1 footnote]
- Accuracy intervals: **2,000 percentile-bootstrap query resamples** (one query/family makes this a superfamily bootstrap); accepted-set precision and rejection intervals: **exact Clopper–Pearson**. No confidence-bound requirement is imposed when selecting the ≥99% *empirical* validation threshold. [§4.8–4.9, lines 359–370]

### Absent labels, strictness, and caveats

- Main CATH evaluation is **closed-set by construction at H**: test families absent after lookup filtering are removed. This is different from evaluating novel-superfamily rejection. Unanswered predictions on retained test queries count **incorrect**, so top-1 accuracy equals macro superfamily recall. [§4.4, lines 298–301; §4.7, lines 335–338]
- Method-specific missing labels remain failures in the full benchmark: train-only **HH-suite3 TEDLH** profiles cover **959/1,028 = 93.3%** of queries. Full-set H accuracy **72.3% [69.7,74.9]**; reachable-only H accuracy **77.5% [74.9,80.1]**. Reachable-only C/A/T/H is **89.1/82.8/79.6/77.5**. Both denominators are explicit; the reachable subset does not replace the headline denominator. [Table 1 caption/footnote; §2.1, lines 71–74]
- Open-set experiment: withhold **50 entire superfamilies from CATH training, TED training, AND reference lookup**, retrain a separate model, and evaluate **1,401 absent-class domains**. At its validation-only cutoff 0.22579, **1,382/1,401 = 98.64%** are correctly rejected; **19 = 1.36%** falsely accepted, concentrated in **two groups**. These queries are not silently dropped. Selection rule/seed for the 50 families is not stated in the main Methods. [§2.4, lines 161–165; §4.10, lines 388–393; Fig. 4b; Table S10 cited]
- “Strict” concerns sensitive **profile-search sequence separation**, both held-out query sets protected from training, CATH-only lookup shared across methods, and TED augmentation filtered against held-out queries. It does **not** mean held-out H labels in the main benchmark, or that frozen-pLM pretraining exposure was excluded. The latter is not claimed/tested here. [§4.4, lines 293–313; last sentence is an inference about the scope of those controls]
- Profile baseline anti-leakage: keep **only TEDLH profiles whose CATH seed belongs to training**; remove self-seeded query profiles and profiles seeded on domains removed by the S20 filter. Filtering just a sequence lookup without filtering profile provenance would not match this benchmark. [§4.7, lines 347–352; Table 1 footnote]
- Stated limitations: TED's automated consensus labels may retain **annotation noise**; predefined **domain boundaries** are assumed; scope is **classes 1–3**; centroid predictions do not supply residue alignments. Small validation/test distribution differences are offered as explanation for empirical test precision falling below the validation target. [Discussion, lines 236–241; §2.3, lines 140–142]
- Comparator caveat: **ProtTucker uses its published CATH v4.3 checkpoint**, not retraining on the matched v4.4 split; CATHe2 *is* retrained on identical splits. **Inference:** current lookup filtering alone does not establish that the old learned checkpoint never saw the benchmark domains/relatives during supervised training. The paper does not resolve that exposure question. [§4.7, lines 345–347]
- Reproducibility caveat: the PDF describes the split/predictions/checkpoint hashes as assembled in a versioned archive **“for release with the preprint”**, and says a matching tagged archive will be linked. That is not itself an accessible manifest/checksum. [Data availability, lines 414–419; Code availability, lines 420–425]
- Numerical inconsistency: Fig. 4d says **5,699 reference superfamilies**; Methods/main Results repeatedly say **5,659**. Treat 5,699 as unresolved, not a second documented split. [Fig. 4d; §2.4, line 169; §4.4, line 300; §4.10, lines 384–385]
- Supplement pointers to obtain before claiming a complete exact replication: **S1** (Table 1 CIs/operating details), **S6** (comparators), **S7** (calibrated thresholds/coverage/precision), **S8–S9** (profile libraries, reachability, comparator parameters), **S10** (absent-family errors), **S4** (runtime/index size); **Supplementary Methods** for optimization. None is present as a table in the supplied PDF; no unobserved entries are asserted here. [Table 1 caption; §2.3, line 136; §4.5, line 318; §4.7, lines 351–352; §4.10, lines 378,393]

## Ankh

- **Source:** Elnaggar et al., supplied `2301.06568v1.pdf`; evaluation description **§4.2.3, EAT paragraph, pp. 12–13**; detailed results **§7.3.4, Table 15**. The body mistakenly directs readers to **Table 16**, which is a different generated-domain analysis. [§4.2.3; §7.3.4–7.3.5]
- Explicit dataset claim: **69k lookup sequences and 219 test sequences**, developed for **ProtTucker** evaluation, from **CATH v4.3**. The paper does not give the exact FASTA filenames, checksums, post-processing counts, or a new split recipe for this evaluation. It claims the existing benchmark, not a larger CATH lookup. [§4.2.3, EAT paragraph]
- Raw embeddings; **no supervised training** for EAT. Transfer from the **closest match** in lookup embedding space; body calls it **k-NN**, without stating a numerical `k`. **Inference:** closest-match caption is consistent with `k=1`, but the paper does not explicitly give that parameter. [§4.2.3; Table 15 caption]
- Last hidden states are used for benchmark contextualized embeddings in general. **EAT-specific residue pooling, special-token exclusion, distance metric, vector normalization, checkpoint revision/precision, duplicate policy, self-hit handling, singleton masking, and level-wise denominators are not specified** in the EAT paragraph/Table 15. Do not substitute the reference EAT code's defaults as evidence of Ankh's actual run. [§2.1, p. 3, last-hidden-states paragraph; §4.2.3; §7.3.4]
- Do **not** infer mean or max pooling from unrelated supervised tasks: global max pooling is described for **regression/binary classification**, not EAT. [§4.2.6, p. 13; §4.2.3]
- Raw **ProtT5-XL-U50 C/A/T/H = 83.6±5 / 70.0±6 / 57.2±7 / 73.3±7 (%)**, mean **71.0±6**. **Ankh-base = 85.8/77.2/63.5/72.7**, mean **74.8**; **Ankh-large = 83.6/72.1/61.0/70.7**, mean **71.7**. Thus the disputed raw ProtT5 H number is explicitly **73.3**, not an Ankh-model number. [Table 15]
- **Best supported conclusion about 73.3 vs 64.0:** unresolved from this PDF. There is no documented change of lookup/query set or metric that explains it. A scoring/denominator difference is a concrete hypothesis: the reference scorer masks unavailable classes per level and enforces ancestor correctness, whereas Ankh only says labels are compared at each level. Independently comparing the final numeric CATH component (e.g. `10`) rather than the full prefix can wrongly count unrelated superfamilies as equal. **This is a hypothesis, not an observed Ankh implementation bug.** [Table 15 caption; EAT `Eval.mask_singletons`, `Eval.add_sample`]
- **Do not use H>T as proof of a bug:** H and T can have different denominators because of singleton masking. At the pinned EAT revision, a direct audit of the bundled FASTAs/CSV gives **150 H-reachable queries**, **208 T-reachable queries**, but **210 T-unmasked queries** under the training scorer's union-based logic. This alone makes cross-level monotonicity an invalid diagnostic. It does not prove the origin of Ankh's 9.3-point gap. [EAT data audit described below; `Eval.__init__`, `mask_singletons`]
- To settle the gap, obtain Ankh's **per-query nearest-neighbour IDs, embedding/preprocessing settings, and exact per-level scoring masks**. Compare those against the already reproduced ProtTucker result before interpreting 73.3 as a better representation. [Requirement inferred from omissions in §4.2.3/Table 15 and explicit reference scorer behavior]

### `train_prottucker.py`: importing a split is not building one

- `DataSplitter` loads the supplied H5 and adjacent **`cath-domain-list.txt`**; labels are whitespace columns **0 = domain ID, 1–4 = integer C/A/T/H**. Comment lines beginning `#` are skipped; labels without an embedding ID are skipped. H is a local numeric component, not globally unique without its ancestors. [lines 263–318, `__init__`, `parse_label_mapping_cath`]
- H5 identifiers are normalized as **`seq_id.split('|')[2].split('_')[0]`**. Nested H5 groups use their first child; flat datasets use the fallback. A dictionary comprehension can silently overwrite entries whose normalized IDs collide. No pooling/normalization is performed here; embeddings are assumed already per-protein. [lines 353–364, `get_precomputed_embeddings`]
- FASTA IDs: take **third `|` field**, otherwise the **entire header without `>`**. Duplicate headers are not added again; their sequence lines still append to that ID's existing sequence. Identical concatenated sequences are then collapsed **within each FASTA independently**, with **the last encountered ID for that sequence retained**. No label-conflict check accompanies sequence collapse. [lines 320–351, `read_cath_ids`]
- The advertised duplicate assertion compares a dictionary's length with a list constructed from the same dictionary, so it does **not** check cross-split duplicates or preserve the original sample count. The duplicate-sequence policy can change which domain label survives. [lines 342–347, `read_cath_ids`; latter consequence is inference]
- Missing embedding IDs cause a print and **`continue`**, silently shrinking the effective set apart from console output. No failure or output manifest records the exclusion. [lines 366–376, `get_embeddings`]
- Default predefined split is **`train74k.fasta`** for training **and validation lookup**, **`val200.fasta`** for validation. It does not construct a 20% filter, test219 split, or lookup69k. The pinned repository tree instead contains **`train66k.fasta`, `lookup69k.fasta`, `test219.fasta`, `test300.fasta`, `val200.fasta`**, but no `train74k.fasta`; this default cannot be resolved from those bundled files alone. [lines 378–396, `get_predef_splits`; revision tree `data/ProtTucker`]
- The `p_test` argument is not used to load test data; supplying both `p_train` and `p_test` leaves local `p_val`/`p_valLookup20` undefined. Do not treat this helper as a working configurable three-way splitter. [lines 378–388, `get_predef_splits`]
- `main` loads the **S100 embedding pool** but restricts actual train/validation samples through the FASTAs; **loading the pool is not itself lookup leakage**. Using all S100 vectors directly as benchmark lookup would bypass that restriction. [lines 935,960–966; `DataSplitter.get_embeddings`]

### Training evaluator: conditional denominators and hierarchical equality

- Search is exact float32 **Euclidean `torch.cdist(..., p=2)`**, default **`n_nearest=1`**, without L2 normalization or explicit self-hit removal. For `k>1`, `mergeTopK` performs majority selection sequentially C→A→T→H, restricting voters to those agreeing with previous choices; it is not four unrelated majorities. [lines 593–600,618–633,659–690]
- `Eval.__init__` builds label membership from **`lookup IDs ∪ query IDs`**, not lookup alone, despite the nearby comment. [lines 552–559]
- `mask_singletons` masks H to NaN when its union membership list has length **1**; higher levels are masked recursively only if there is one remaining child branch. `add_sample` skips NaNs separately at each level. Thus reported accuracy uses **different level-specific denominators**, not necessarily all 219 queries. [lines 602–615,635–647,669–670]
- **Important defect/qualification:** union-based singleton masking does **not** exactly test “a correct answer exists in lookup.” Two queries of the same H with no lookup member keep each other unmasked; similarly, an absent topology with several query-only H groups can remain unmasked. Query-set composition can therefore change the denominator even with a fixed lookup. [lines 556–558,635–647; inference from those conditions]
- Scoring enforces the **whole hierarchical prefix**: after the first nonmasked mismatch, all deeper levels count wrong even if their local integers match. Comparing only `H=10` or only a local topology integer does not reproduce this scorer. [lines 602–615, `add_sample`]
- Training's `testing` is called on **validation** despite the “test” names; validation selects checkpoints/early stopping. Checkpoint criterion is **H accuracy `acc[3][-1]`**, improvement **`> 1e-3`**, with **20 nonimproving epochs** allowed. It is not threshold calibration and does not use the C/A/T/H mean as its actual criterion. [lines 845–855,911–921,951–952,964,994–1004]
- Training DataLoader uses **`shuffle=True, drop_last=True`**: a partial final minibatch is omitted during training, not evaluation. Default `CustomDataset(..., balanced_sampling=False)` iterates domains rather than balanced H labels. These affect supervised training, not the raw frozen split. [lines 66–83,884–892,966]

### `eat.py`: generic inference is a different evaluator

- Inputs are exactly the supplied **`.fasta` or `.h5`** files; there is **no built-in identity/redundancy filter, split builder, label-availability filter, or lookup/query overlap rejection**. The caller owns those decisions. [lines 207–225,249–273,373–406]
- FASTA parsing differs from training: UniProt `>tr`/`>sp` headers use the **second `|` field**, all others the entire header without `>`; replace **`/` and `.` with `_`** in IDs, uppercase sequences, remove whitespace and **`-`** gaps. Duplicate/colliding IDs overwrite earlier records. **Identical sequences under different IDs are retained**, unlike `read_cath_ids`. [lines 275–301, `read_fasta`]
- H5 loading reads all top-level arrays and stacks them; if the **first key starts with `cath`**, normalize **all** IDs via third pipe field and underscore truncation. Unlike the training dictionary normalization, normalization is into a list, so colliding normalized IDs remain as separate vector rows. No sequence deduplication is possible from vectors alone. [lines 303–314, `read_embeddings`]
- FASTA embeddings use **`Rostlab/prot_t5_xl_half_uniref50-enc`**, fp16 encoder, eval/no-grad; replace **U/Z/O→X** (not every nonstandard letter); use last-layer states and mean the first **`s_len` residue positions**, excluding following special/padding tokens. No vector L2 normalization or trained head unless `--use_tucker` is nonzero. [lines 131–143,159–202,219–221]
- **Potential query/lookup loss bug:** flush condition includes **`seq_idx == len(id2seq)`**, impossible for zero-based `enumerate`; there is no post-loop flush. A final batch below the size/residue/length triggers is omitted. RuntimeError also skips the attempted batch. `max_seq_len=1000` triggers processing; it does **not** truncate or exclude long domains by a stated biological length policy. [lines 159–202, `get_embeddings_batch`; static control-flow inference, not a reproduced model run]
- Labels are **opaque CSV strings**, just `split(',')[0]` and `[1]`; no header handling, dotted-CATH parsing, multi-label support, or subset validation. Missing label keys raise during prediction; duplicate CSV IDs keep the last value. If no label file is supplied the actual labels are **`None`**, although CLI help claims IDs are interpreted as labels (IDs are still present in output). [lines 316–325,399–403,421–424]
- Search defaults: **Euclidean `p=2`**, raw embeddings (**`--use_tucker 0`**), **`--num_NN 1`**, **`--threshold None`**. Increasing `num_NN` outputs separate neighbour rows; it does **not** vote. There is no built-in reliability fitting or validation-threshold selection. [lines 338–347,373–406,457–470]
- Threshold skips rows only if **`distance > threshold`**, so equality is accepted. Rejected queries have **no row**, not an explicit rejected outcome. `Evaluator` uses **only `nn_iter == 0` among surviving prediction rows**; with thresholding its accuracy is accepted-set accuracy, not full-query accuracy/coverage. If all predictions are rejected, unpacking the empty list fails. [lines 45–51,65–75,395–403]
- Generic evaluator does **not mask unreachable labels** or enforce the CATH hierarchy. It uses sklearn exact-string accuracy, weighted F1 and balanced accuracy. A correctly formed dotted prefix label can be scored, but per-level CATH evaluation must be implemented externally. Bootstrap skips draws where predicted labels are not a subset of the sampled true labels, conditioning the uncertainty sample rather than taking an ordinary query bootstrap. [lines 45–96, `Evaluator`]
- **Small data audit, not a model rerun:** pinned `data/ProtTucker/test219.fasta` has **219 IDs / 219 distinct sequences**; `lookup69k.fasta` has **69,605 IDs / 69,605 distinct sequences**; their ID intersection is **0**. With bundled `data/cath_v430_dom_seqs_S100_161121_labels.txt`, lookup-prefix reachability at C/A/T/H is **219/219/208/150**; union-singleton unmasking gives **219/219/210/150**. Counts were computed directly from FASTAs/CSV and the scorer's conditions, not from embeddings or predictions. This concretely demonstrates the two-query T-denominator discrepancy. [revision-pinned data files; `Eval.mask_singletons`, lines 635–647]

## Requirements implied

- **Freeze three explicit domain-ID manifests: lookup, calibration, test; pin CATH release/files and sampling seed, and record counts after every filter.** Do not rely on filenames like “69k” or methods prose to define membership. [ContrasTED §4.4; EAT `get_predef_splits`, `get_embeddings`]
- **For a ContrasTED-style S20 track, use CATH v4.4 classes 1–3; choose one query per H family per held-out set; filter candidate lookup against both query sets using profile-search ≥20% identity, sensitivity 7.5, three iterations, 80% coverage of both sequences.** Recover/pin the actual search command/version before claiming exact replication. [ContrasTED §4.4, lines 293–301]
- **Make preprocessing explicit: domain boundaries, discontinuous-segment order, length inclusion, alphabet mapping, ID normalization, duplicate-sequence representative and conflicting-label policy. Check both ID and sequence overlap across all three roles.** Match 16–2,000 residues/chain-order concatenation only when claiming this paper's preprocessing. [ContrasTED §4.1; EAT `read_cath_ids` versus `read_fasta`]
- **Define closed-set reachability from lookup alone, using full CATH prefixes at each level; freeze the eligibility masks before comparing models.** If excluding H-unreachable queries as ContrasTED does, publish excluded IDs/counts. Do not copy EAT's lookup∪query singleton heuristic unnoticed. [ContrasTED §4.4, lines 298–301; EAT `Eval.__init__`, `mask_singletons`]
- **Keep a separate open-set panel when evaluating novel-family rejection; remove those families from every labeled lookup/training source and report rejection/false acceptance, rather than silently excluding them.** Never mix its separately fitted model/threshold with the closed-set result. [ContrasTED §4.10, lines 388–399; Fig. 4 caption]
- **Fit distance/normalization/k choices and each pLM/task/level threshold on calibration only; choose the most permissive accepted set meeting the stated empirical precision target, then freeze the cutoff.** Report “no feasible cutoff” if appropriate; do not import 0.24048 or a learned-ProtTucker threshold into raw embeddings. State minimum support/uncertainty requirements if adding them; these are additions, not this paper's exact criterion. [ContrasTED §§4.8–4.10; §2.3, frozen-baseline failure]
- **Report ungated full-query accuracy, accepted coverage, accepted-set precision, their denominators and intervals separately. Count unanswered predictions as incorrect for full-set accuracy; give method-specific reachable-only results additionally, never as an unlabeled substitute.** [ContrasTED §4.7; Table 1 HH-suite3 footnote; EAT `Evaluator` survivor-only behavior]
- **Compare globally unique prefixes (`C`, `C.A`, `C.A.T`, `C.A.T.H`), not isolated local CATH integers; save nearest-neighbour IDs and per-query outcomes/masks.** Reconcile the Ankh discrepancy using those artifacts rather than assuming its nominal 69k/219 description establishes protocol equivalence. [EAT `Eval.add_sample`; Ankh §4.2.3/Table 15]
- **Assert input/output embedding counts and exact ID coverage; fail or explicitly ledger missing embeddings, collisions and rejected rows.** Do not let batch-tail loss, RuntimeErrors or missing precomputed vectors silently redefine a split per pLM. [EAT `get_embeddings`, `Embedder.get_embeddings_batch`, `read_embeddings`, `get_NNs`]
- **Keep raw frozen 1-NN results distinct from centroids, structural modalities, contrastive projection, and externally pretrained supervised checkpoints.** Record pooling/metric/normalization and supervised-exposure caveats for every comparator. [ContrasTED Table 1, §§4.1–4.3,4.7; Ankh's underspecified EAT paragraph]
